# Data Visualization

## Mission
Create project-controls visualizations that answer operational questions rather than decorate dashboards.

## Rules
- Every chart needs a clear question and interpretable labels.
- Prefer direct labeling and useful tooltips.
- Use consistent semantic meaning for planned, actual, verified, delayed, and critical states.
- Avoid 3D, gratuitous gradients, chartjunk, and unnecessary legends.
- Show data date where schedule interpretation depends on it.
- S-curves should clearly distinguish baseline/current plan/verified actual.
- Duration comparison should reveal outliers.
- Delay-cause charts should support comparison.
- Confidence distribution must not be presented as “AI accuracy” unless accuracy was actually measured.
- Empty/small-sample states must be honest.
- Project Memory insights must show sample size and synthetic-demo labeling where relevant.

## Interaction
Where useful, chart selections should filter or drill into the underlying activities/events.
