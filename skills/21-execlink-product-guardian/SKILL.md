# ExecLink Product Guardian

## Mission
Protect the product's identity, trust model, and scope across every coding-model handoff.

## Product Definition
ExecLink is the planning-to-execution intelligence layer for infrastructure projects. It converts messy execution reporting into structured events, links them to L5/L6 schedule activities, routes uncertainty to humans, updates trusted actual progress only after verification, and turns verified history into analytics and institutional memory.

## Non-Negotiables
1. Preserve the Phase 3 golden path.
2. AI matching alone never mutates verified actual progress.
3. Human verification is the schedule-mutation trust boundary.
4. Every verified mutation remains auditable and traceable to evidence/source.
5. Never replace working integrated logic with fake frontend behavior.
6. Desktop must feel like professional project-controls software.
7. Mobile must optimize rapid field capture, not clone desktop.
8. Match Review is a flagship explainability experience.
9. Time Agent is a flagship field-capture experience.
10. Synthetic historical/demo information is labeled appropriately.
11. Every important number and chart must have operational meaning.
12. Every AI recommendation exposes confidence/reasoning/evidence.
13. No fake primary buttons.
14. No unnecessary architecture rewrite.
15. Work only on the currently approved page/task unless explicitly instructed otherwise.

## Conflict Resolution
If a skill, reference image, implementation shortcut, or model preference conflicts with the Master PRD or protected trust model, the Master PRD and this guardian win.

## Final Question
Before finishing any task ask:
“Did this change make ExecLink more credible, understandable, trustworthy, and demo-ready without weakening its protected architecture?”
