# Design System Guardian

## Mission
Ensure every page feels like one product even when different models contribute code.

## Canonical Primitives
Prefer/reuse concepts such as AppShell, Sidebar, TopBar, ProjectSwitcher, PageHeader, SectionHeader, StatusBadge, ConfidenceBadge, DisciplineBadge, DataTable, FilterBar, Drawer, Modal, Tooltip, EmptyState, ErrorState, Skeleton, Timeline, EvidenceViewer, SignalBreakdown, ConfidenceMeter and chart primitives.

## Rules
- Use shared spacing, typography, radii, colors, border, motion, and state tokens.
- Do not introduce arbitrary hex values inside random page components when a token exists.
- Do not create a new badge style for every page.
- Equivalent actions should look and behave equivalently.
- Maintain consistent table row height, input height, button sizing, card padding, and page gutters.
- Extend the design system deliberately when a genuinely new product concept appears.

## Before Adding UI
Search for an existing component/token first.

## Acceptance
Place any two ExecLink screens side by side: they should clearly belong to the same application.
